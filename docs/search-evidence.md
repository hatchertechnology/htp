# Saved search evidence (partial H05)

`POST /websites/{id}/search/dataset` accepts `site_url`, `start_date`, `end_date`, `dataset`, optional zero-based `offset` and `limit` (1–100). It authorizes the website and validates the property and dates, then reads the latest exact-period saved snapshot; it never requests Google or creates a collection job. Datasets are `queries`, `pages`, `query_pages`, `devices`, `countries`, `analysis`, and `landing_outcomes`. Rows come from the latest exact-period saved snapshot; daily canonical history alone cannot reconstruct these dimensions. `available: false` and `reason` distinguish absent snapshots or datasets from an empty observed result. `has_more` paginates retained rows, not Google's unreturned rows. `collection`, `measurement`, and analysis policy/coverage are preserved when present. `sync` identifies the exact snapshot and its own fetched time/state; `daily_sync` separately describes canonical daily history and provider status. The semantics version is 1. Query rows exclude anonymized searches and Google does not guarantee a complete inventory. Landing outcomes use the site's GA4 binding, include all channels and are not attributed to search queries; sampled or thresholded results remain unavailable. Currency is unknown unless supplied by the provider.

The API reads one page through `read_search_dataset_page` (migration `20261204000000_search_bounded_dataset.sql`), a `security definer` function that re-checks `auth.uid()` and the nonanonymous claim and selects only the requested page from the latest matching snapshot. The full snapshot is never returned to the API process, so a page read no longer transfers or decodes every dataset. The function independently validates kind, property, dates, dataset, offset (0–5000), limit (1–100), the optional segment `device`/lowercase three-letter `country` filter, and rejects filters on other datasets. Legacy snapshots without a dataset, or with an explicit `unavailable` marker, return the existing `dataset_unavailable`/reason states rather than synthesized rows. The encoded result must fit the byte budget or the read fails closed with `search_page_too_large`; a partial page is not returned because the existing caller advances a fixed offset. Applying the migration and its narrow authenticated `execute` grant is a separate, reviewed deployment step; the endpoint stays behind `HTP_ROLLOUT_SEARCH_EVIDENCE` and off by default.

Inspection history uses the existing owner-scoped `search_inspection_history` RPC, with its append-only cursor and owner-submitted provenance. An inspection concerns Google's indexed version and is not a live test.

The saved-evidence and crawl surfaces default off in both API and web; see `docs/wave1-rollout-gates.md` for their flags and sequencing. Deploy the API before the web proxy/UI, but enable each surface only after its migrations, narrowly scoped grants, provider and authenticated end-to-end checks, and recovery plan are separately reviewed. Existing dashboards and saved-data contracts remain available. This is not full H05: live verification and independent review remain outstanding. Snapshot pagination does not supply missing upstream observations or historical dimensions for arbitrary periods. Fixture tests do not establish production readiness.

Analysis candidates with array evidence return at most 25 evidence rows each, with `evidence_presentation` recording retained and returned counts and truncation. The full evidence remains in the saved source snapshot and the paginated `query_pages` dataset.

`query_page_segments` is a separate optional Google collection of at most 1,000 query/page/device/country rows. An eight-second optional collection deadline or segment-specific failure is saved as unavailable without discarding the primary report. The `device` and lowercase three-letter `country` filters apply only to retained rows, before pagination; absence from that bounded set is not zero activity. Earlier snapshots have no segment data. Collection adds an upstream request and may need multiple syncs before a selected period has evidence; it does not run from the reader.

The H01 seam `search_crawl_evidence(website, delivery, exact URL, finding cursor, evaluation cursor, limit)` returns at most 50 findings and evaluations per call, immutable source ordinals, matching S01 entity IDs, relevant returned-rule coverage, source/scan/binding provenance and contract versions. Oversized individual evidence is omitted with an explicit flag; full evidence remains in the immutable detail. It never maps absent findings to a pass and always reports coverage unknown. Matching is exact, not canonicalized. Imported observations remain labeled with their original ingestion source. A bounded read can time out on exceptionally large retained reports; it never schedules a scan. The HTTP `/search/crawl-evidence` route and UI consume this seam independently from lifecycle's transitions.

Rollout requires additive migrations `20261123000000_search_crawl_evidence.sql`, `20261123000001_search_exact_snapshot.sql`, and `20261204000000_search_bounded_dataset.sql`, followed by separately reviewed narrow grants and API, web, and collector releases. All new surfaces remain held by default. The API and Google worker each require `HTP_ROLLOUT_SEARCH_EVIDENCE=true`; the web requires `NUXT_PUBLIC_ROLLOUT_SEARCH_EVIDENCE=true`. The worker flag separately enables the optional previous-period and segmented provider requests; deploying the worker alone does not activate those requests. Verify provider quota, snapshot size, existing-report compatibility, worker deadlines, authenticated access and recovery before enabling. Disable web first and then the API/worker to hold the feature; this does not revoke database access or erase saved data. Any regrant or database rollback is a separate reviewed operation that preserves newer observations.

Dataset offsets are applied to the latest exact-period snapshot on each read. If collection replaces that snapshot between pages, rows may move; clients that need a stable audit must use the retained immutable source snapshot rather than treating these offsets as a durable cursor.
