# Saved search evidence (partial H05)

`POST /websites/{id}/search/dataset` accepts `site_url`, `start_date`, `end_date`, `dataset`, optional zero-based `offset` and `limit` (1–100). It authorizes the website and validates the property and dates, then reads `request_google_report`; it never requests Google or creates a collection job. Datasets are `queries`, `pages`, `query_pages`, `devices`, `countries`, `analysis`, and `landing_outcomes`. Rows come from the latest exact-period saved snapshot; daily canonical history alone cannot reconstruct these dimensions. `available: false` and `reason` distinguish absent snapshots or datasets from an empty observed result. `has_more` paginates retained rows, not Google's unreturned rows. `collection`, `measurement`, `sync`, and analysis policy/coverage are preserved when present. The semantics version is 1. Query rows exclude anonymized searches and Google does not guarantee a complete inventory. Landing outcomes use the site's GA4 binding, include all channels and are not attributed to search queries; sampled or thresholded results remain unavailable. Currency is unknown unless supplied by the provider.

Inspection history uses the existing owner-scoped `search_inspection_history` RPC, with its append-only cursor and owner-submitted provenance. An inspection concerns Google's indexed version and is not a live test.

Deploy the API before the web proxy/UI. The initial slice required no migration. Roll back web and API releases independently; neither changes stored observations. Existing dashboards and saved-data contracts remain available. There is no separate feature flag: defer the web release if the API route is unavailable. This is not full H05: live verification and independent review remain outstanding. Snapshot pagination does not supply missing upstream observations or historical dimensions for arbitrary periods. Fixture tests do not establish production readiness.

Analysis candidates with array evidence return at most 25 evidence rows each, with `evidence_presentation` recording retained and returned counts and truncation. The full evidence remains in the saved source snapshot and the paginated `query_pages` dataset.

`query_page_segments` is a separate optional Google collection of at most 1,000 query/page/device/country rows. An eight-second optional collection deadline or segment-specific failure is saved as unavailable without discarding the primary report. The `device` and lowercase three-letter `country` filters apply only to retained rows, before pagination; absence from that bounded set is not zero activity. Earlier snapshots have no segment data. Collection adds an upstream request and may need multiple syncs before a selected period has evidence; it does not run from the reader.

The H01 seam `search_crawl_evidence(website, delivery, exact URL, finding cursor, evaluation cursor, limit)` returns at most 50 findings and evaluations per call, immutable source ordinals, matching S01 entity IDs, relevant returned-rule coverage, source/scan/binding provenance and contract versions. Oversized individual evidence is omitted with an explicit flag; full evidence remains in the immutable detail. It never maps absent findings to a pass and always reports coverage unknown. Matching is exact, not canonicalized. Imported observations remain labeled with their original ingestion source. A bounded read can time out on exceptionally large retained reports; it never schedules a scan. The HTTP `/search/crawl-evidence` route and UI consume this seam independently from lifecycle's transitions.

Rollout order for this increment: apply additive `20261123000000_search_crawl_evidence.sql` first, deploy API, deploy web, then deploy the Google sync collector. Roll back collector and web/API first. After consumers have been removed, rollback may drop only `public.search_crawl_evidence(uuid,uuid,text,integer,integer,integer)`; no stored data is deleted. Segment collection is currently not separately feature-gated, so its worker deployment is the activation boundary. Confirm quota, snapshot size, existing-report compatibility and the worker's deadline in a controlled live rollout before declaring readiness.

Dataset offsets are applied to the latest exact-period snapshot on each read. If collection replaces that snapshot between pages, rows may move; clients that need a stable audit must use the retained immutable source snapshot rather than treating these offsets as a durable cursor.
