# SEOsmith lifecycle comparison (read contract v1)

HTP reads immutable saved audit details; comparison does not start a crawl or change a report. The UI chooses a baseline by saved delivery ID. It loads at most ten contiguous runs already present in the history list, stopping at an incompatible run. First/last observed and reopened states describe that loaded window, not the entire retained history. The selection and lifecycle are computed on demand and are not a durable index or notification event stream. Individual URL results are limited to the first 100 on screen; large property values are abbreviated with pointers to the original reports. The source reports remain available for download.

For schema 2 / evidence contract 1, comparisons require matching summary comparison key, engine and ruleset and matching S01 policy digest. Each transition requires explicit eligible, completed pass/fail evaluations with the same rule and validator versions. A missing, omitted, unavailable, uninstrumented or unknown evaluation is `not_observed`, not a pass. A pass-to-fail is new since the selected baseline, or reopened when an earlier failure exists in the loaded compatible window. A fail-to-pass is resolved; fail-to-fail is persisting or changed according to stored finding evidence. Earlier failures remain visible when later checks are unknown. First/last timestamps use the saved scan time and are bounded by the loaded window; they are not per-fetch timestamps. Per-rule coverage reports the producer's stored-entity denominator, attempted and unknown counts, and excluded (ineligible plus unknown eligibility); it does not count the unvisited web.

URL identity uses the S01 entity ID and exact stored URL. Available observations from both runs are required for changes; missing or unavailable observations are not removal. Response fields are compared when available; HTML metadata, body hash and link/relationship arrays require successful HTML on both sides and complete extraction. Missing optional fields remain unknown, not empty. Property values and JSON pointers reference the retained baseline/current reports. This does not invent S03 freshness, S05 link-context or S06 semantic-content evidence.

Legacy schema 1 retains the existing whole-run conservative comparison. Unknown future schemas are not comparable. The v1 read result is an HTP-side interpretation, not a changed SEOsmith wire format; no migration, producer change or new receipt is required. S01 receiver support and validated v2 reports must exist before using this interpretation. No new production flag is activated by this code. Rollback restores the previous web build; retained reports remain unchanged and v2 receiver support must remain for retained v2 reports. S14 and other future contracts need separately versioned comparison semantics before use.

Release requires independent review of the exact revision, tests against retained v1/v2, partial and truncated producer fixtures, authorization and performance checks through real reads, and a receiver-first end-to-end canary with exact receipt/source preservation. Fixture tests alone are not production verification. A full-history indexed lifecycle/read API, pagination of changes, cross-surface integration and richer producer evidence remain follow-on work; do not close H03 on the basis of this bounded UI alone.
