# Static recipient confirmation

Source-only slice. The assets-only `/forms/confirm` page selects Rust `POST /forms/confirm` only when `public.staticDashboard` and the independent `public.rolloutFormsConfirmation` are exactly true. Legacy mode retains `/api/forms/confirm` and its existing gate. The fragment remains `recipient_uuid:lowercase_64_hex_token`; mounting removes the fragment before interaction. Tokens travel only in the JSON request body. Do not capture tokens in screenshots, URLs or request logs.

Rust requires exact `HTP_FORMS_CONFIRM_API=true`, `SUPABASE_URL`, and server-only `FORMS_SERVICE_KEY`. Unset flags stay off. Reuse `HTP_DASHBOARD_CORS_ORIGIN` for the single exact dashboard origin; no credentials or wildcard CORS. No owner bearer is needed: the invitation challenge is the credential. No recipient management or delivery is enabled.

The route accepts only `application/json`, at most 1024 bytes, with exactly `recipient_id` and `token`. It bounds body reads and the RPC to ten seconds (the reqwest request deadline includes response reading); the browser has a twelve-second deadline. There are no automatic retries or redirects. Only database boolean true becomes `{ok:true}`; false is a safe refusal, and any other upstream outcome is unknown. Raw upstream errors are never returned or logged. The page confirms only typed `{ok:true}` and uses fixed failure text.

When enabled, confirmation admission is local and shared across router clones: at most four handlers (including body reads and upstream response reads) and 30 admissions per monotonic 60-second fixed window per process. The first window starts at router construction; a request at or after expiry resets it. Saturation, exhausted budget, or counter contention returns `429 {"code":"rate_limited"}`, `Cache-Control: no-store`, and `Retry-After: 60` immediately, before reading the body or contacting PostgREST. The existing outer exact-origin CORS layer covers these errors and answers preflights without spending budget. Retry-After is conservative advice, not a reservation; the browser retains its fixed error text and never automatically retries. Disabled/missing configuration still returns 404 before admission.

Admission uses the public ingress semaphore pattern, with a fixed-size local counter instead of its database-backed keyed limiter: charging that limiter would itself create an RPC per request. No tokens, UUIDs, IP addresses or proxy headers are retained as limiter keys, and there are no limiter logs, cleanup tasks, queues, new settings or external services. Malformed admitted requests also consume budget; attempts are never refunded after failure or cancellation. Fixed windows allow up to 60 admissions around a boundary; four in-flight remains the concurrent cap. Limits are per process, reset on restart, and multiply with replicas; this is bounded local backend protection, not a distributed or per-person quota. An attacker can exhaust this shared budget and temporarily deny legitimate confirmation. No live scaling/configuration change is part of this source follow-up.
