# Remediation foundation (held)

This is a held workflow for saved schema 1/2 audit findings. The dashboard, authenticated proxies and API routes are default off via `NUXT_PUBLIC_ROLLOUT_REMEDIATION` and `HTP_ROLLOUT_REMEDIATION`; neither flag grants database access. The migration keeps table and function privileges held for anon, authenticated and service_role and fails on effective inherited privileges. It intentionally differs from the previously reviewed December 2 SQL, which granted authenticated function execution and service_role table access. The candidate also rejects a missing schema version and a non-string finding key instead of allowing SQL NULL semantics or text coercion. The earlier renumber-only reviews do not review these changes or their composition with current main.

Work is bound to the owner, current website hostname, saved audit and original finding index. It is separate from the audit. `done` and `excepted` are workflow states; an `observed` or `unverified` attempt is a user-entered observation, not a verified resolution. This does not implement lifecycle verification or H15 notification. Business exposure and effort are user-entered, not provider-backed estimates. Schema 4, S14 policy, revenue predictions, and producer activation are out of scope.

The migration follows Forms pilot scope `20261201000000`; reconcile migration ledger and reservations before any deployment. Activation requires separate review, an authorized privilege and API rollout, and end-to-end validation. Keep both flags off and privileges held until then. If subsequently enabled, disable the UI and access first for rollback and preserve existing records; tests on disposable fixtures do not establish production readiness.
