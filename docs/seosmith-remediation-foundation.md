# Remediation foundation (held)

This is a held workflow for saved schema 1/2 audit findings. The dashboard, authenticated proxies and API routes are default off via `NUXT_PUBLIC_ROLLOUT_REMEDIATION` and `HTP_ROLLOUT_REMEDIATION`; neither flag grants database access. The migration keeps table and function privileges held for anon, authenticated and service_role and fails on effective inherited privileges. It intentionally differs from the previously reviewed December 2 SQL, which granted authenticated function execution and service_role table access. The candidate also rejects a missing schema version and a non-string finding key instead of allowing SQL NULL semantics or text coercion. The earlier renumber-only reviews do not review these changes or their composition with current main.

Work is bound to the owner, current website hostname, saved audit and original finding index. It is separate from the audit. `done` and `excepted` are workflow states; an `observed` or `unverified` attempt is a user-entered observation, not a verified resolution. This does not implement lifecycle verification or H15 notification.

The panel keeps the H04 priority inputs separate (`h04-priority-1`). Technical severity comes from the saved finding. Evidence confidence, rule/validator attribution and expected value are shown only when exactly one explicit failed evaluation with schema 1 evidence-contract provenance points to that saved finding and records confidence exactly as `high`; missing provenance, missing confidence and `unknown` stay unknown. Affected reach counts distinct observed valid saved finding URLs for the finding's rule. It is known only from the receiver-derived coverage on the saved summary: schema 1 requires complete crawl coverage, and schema 2 with a supported version 1 evidence contract requires complete crawl and evaluation coverage. A raw legacy report claim, an unsupported contract or a missing summary field does not establish completeness. Invalid or missing finding URLs are excluded and make the count inconclusive. Otherwise the observed count is a lower bound, not a website-wide total, and site-wide reach is unknown. Intended policy is unavailable because a schema 1/2 report carries collection policy, not owner intent; it needs H02/S14. No scalar score, ordering weight or predicted revenue/recovery amount is produced. Business exposure, estimated effort and recommendation rationale are owner-entered planning fields, not provider-backed estimates, and are labeled not assessed until recorded. Schema 4, S14 policy, revenue predictions, and producer activation are out of scope.

The migration follows Forms pilot scope `20261201000000`; reconcile migration ledger and reservations before any deployment. Activation requires separate review, an authorized privilege and API rollout, and end-to-end validation. Keep both flags off and privileges held until then. If subsequently enabled, disable the UI and access first for rollback and preserve existing records; tests on disposable fixtures do not establish production readiness.
