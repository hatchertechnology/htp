# Lifecycle index synthetic benchmark

Run `supabase/benchmarks/lifecycle-pg17/run.sh` from this checkout with Podman and the named local PostgreSQL 17 image. It creates an isolated, temporary container and synthetic tables; it does not contact hosted PostgreSQL. It inserts 100 synthetic retained rows directly, applies the lifecycle migration, backfills in two batches, times one trigger-indexed insertion, and reads one finding page and one URL page. The generated report has 128 observations, 512 evaluations, and about 726 KiB JSON; direct fixture insertion bypasses the receiver validator and this is not an end-to-end ingestion measurement. The container is removed on exit.

One local run on PostgreSQL 17.11 (2026-11-21) measured 2.897 s and 3.245 s for two batches of 50, 64.1 ms for one direct trigger-indexed insertion, 3.47 ms for a 50-row finding page and 2.02 ms for a 50-row URL page. An earlier run measured 4.304 s / 5.138 s, 106.9 ms, 5.19 ms and 2.30 ms respectively. The resulting evaluation and URL indexes occupied 38 MiB and 11 MiB for 101 synthetic runs. Results vary with hardware and fixture compressibility. The report was about 42 KiB compressed; it does not represent maximum-size, high-entropy reports, large production datasets, concurrency, receipt validation, network latency or production resource limits. Measure those separately before release.
