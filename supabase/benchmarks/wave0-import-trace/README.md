# Owner-import trace diagnostic

This additive migration instruments only the existing owner import RPC. After the ownership and non-anonymous checks, it accepts only a bounded, syntactically valid W3C v00 traceparent, puts `htp-import:<32 lowercase hex>` in transaction-local `application_name`, and emits fixed PostgreSQL LOG entry/complete/error/canceled markers. It does not log report bytes, user IDs, credentials, URLs, upstream text or free-form header values, and makes no audit-table writes. Error markers include PostgreSQL's five-character SQLSTATE. The function retains the 20-second setting, search path and existing authorization and import logic. A PL/pgSQL exception block adds a subtransaction: measure overhead and independently review rollback/error behavior before deployment.

Trace headers are untrusted and can be supplied directly by a caller. Syntax validation prevents arbitrary text in the markers; it does not prove the ID came from the API or confer authorization. Correlation requires the independently observed API-generated ID, UTC window, and a matching marker. Do not use this as an access-control or audit identity.

`application_name` can be sampled in `pg_stat_activity` after function entry; select only `application_name`, state and wait event, not query text or parameters. A single sample cannot prove a request did not enter or later commit. Markers do not expose pool acquisition, gateway queueing, inbound upload, JSON parsing before function entry, or earlier ownership check. A fast failure can be missed by session sampling. PostgreSQL LOG records may be unavailable, filtered, delayed or truncated by hosted infrastructure, regardless of the local test. A cancel marker means SQL raised `query_canceled` in the instrumented block; client timeout alone is not cancellation. Other termination modes can prevent a marker. Database errors logged by the platform independently of these markers may contain sensitive context; do not print or share raw provider logs.

## Local reproduction

Run `TMPDIR=/var/tmp PGPORT=<free-port> RESTPORT=<free-port> bash supabase/benchmarks/wave0-import-trace/run.sh`. Requires Podman, Python requests and existing pinned images. Disposable local PostgreSQL 17.11 and PostgREST 14.18 apply all migrations, use synthetic credentials and one connection. It verifies successful import, validation failure, a 3-second local statement timeout while waiting on an advisory lock, absence of the canceled delivery, marker visibility, transaction-local reset, invalid header and body sentinel exclusion, and a second request queued before connection acquisition. Finally it restores the saved function using `rollback.sql` and compares its definition to baseline. This test is local and does not establish hosted logging or the production timeout mechanism.
