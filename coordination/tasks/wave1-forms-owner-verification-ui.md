# Forms owner domain verification UI

Status: draft, not release-ready. No production deployment, enablement, credential use, or Formspree changes performed. Review and owner readiness are required before enablement.

The eligible owner signs in normally, opens Websites, and selects Verify domain for the bound website. The exact managed FQDN is displayed and cannot be edited in this flow. Create DNS challenge calls `begin_form_host_verification` once; the returned public TXT name and value remain in component memory while the panel is closed or DNS is published. The owner can select and copy the value. Verify DNS record calls `form-verify`; failure retains the challenge, and after 24 hours the UI asks for a new explicit challenge. Nothing persists or logs the challenge in the UI. No Forms tables, inbox, save, submission, status, or notification operations are invoked by this component. Closing the page or changing user/site clears the in-memory challenge.

`NUXT_PUBLIC_ROLLOUT_FORMS_VERIFICATION` defaults false. When enabled, it takes precedence over existing Forms panels on Websites; eligibility reuses the server-owned pilot binding and verified dashboard session, with the existing database gate authoritative. The other rollout defaults are unchanged. No flags were enabled.
