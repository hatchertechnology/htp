Changed only the confirmation API, its focused offline tests, confirmation documentation, and this report. The feature remains default-off under the existing exact flag and credential checks. No SQL edits, hosted probes, delivery/sends, live configuration, external infrastructure, agents, push, merge or deployment.

Implementation: share one fixed-size admission state through `Arc` across router clones. Reuse the public ingress's immediate semaphore pattern, with four handler slots held across body reads, RPC and response reads. Add a monotonic fixed-window counter: 30 admissions per 60 seconds per process. Check readiness first, admission second, then headers/body and upstream. Semaphore saturation, exhausted window or counter contention rejects immediately without waiting, reading the body or making any RPC. Failed/malformed/cancelled admitted requests consume budget; cancellation releases capacity. Existing request/response bounds, deadlines, no retries/redirects and no token logging remain.

The ingress `charge_form_client` shared keyed limiter requires a database call, verified client identity/hash configuration and persistent keys; reusing it would still allow an RPC per rejected confirmation attempt. This narrower mechanism uses no attacker-controlled key storage, identifiers, proxy headers, cleanup task or new dependency/configuration. State is constant-size. Responses are `429 {"code":"rate_limited"}` with JSON content type, `Cache-Control: no-store`, `Retry-After: 60`. The existing outer exact-origin CORS layer keeps the error body readable to the configured static dashboard; preflight does not consume admission. No automatic retry is added.

Limits: per process, reset by restart and multiplied by replicas. Fixed windows can admit 60 requests around a boundary; concurrent handlers remain capped at four. Retry-After is conservative advice, not guaranteed admission. An attacker can exhaust the shared budget and temporarily deny legitimate users; this is local backend admission protection, not a distributed fairness quota. No operational scaling assertion is introduced.

Focused regressions cover shared budget with rotating UUIDs/tokens and counted loopback RPCs; zero body polling/RPCs on rate and concurrency rejection; exact-origin safe 429 and uncharged preflight; all four slots held by pending bodies; task cancellation releasing slots without refunding attempts; counter contention; precise rollover; disabled precedence; existing strict input and safe upstream mapping.
