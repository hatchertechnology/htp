# Local saved-detail checks

Synthetic loopback fixtures only. Build the API (`cargo build -p htp-api`) and web (`cd apps/web && npm ci && npm run build`) first; the native runner requires the two locally cached container images named in `run.sh`, Podman, and the existing remediation-native issuer and seed. From the repository root, run `bash scripts/bounded-dashboard-native/run.sh`. It creates and destroys a disposable PG17 database and imports only the two checked-in synthetic reports. The native test compares receiver/API, old proxy and opt-in dashboard summaries and raw report bytes, checks browser downloads, and checks a signed nonowner denial.

For delayed, empty, cut, and non-JSON responses, also install the locked `supabase` test dependencies and run `node scripts/bounded-dashboard-native/failure-browser.mjs` from the repository root. It uses the repository migration chain in an isolated PGlite database and a loopback mock API; it binds port 38293. The native and failure fixtures never use a hosted service. For the full 120-second stalled-body and early no-store check, run `node scripts/bounded-dashboard-native/deadline.mjs "$PWD/apps/web"` (port 38294). These tests are not a production capacity qualification.
