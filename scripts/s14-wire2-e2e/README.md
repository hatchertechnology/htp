# Wire-2 local E2E work in progress

These tools use only a dedicated local test stack. They are not a deployment or R6 runner.

* `generate_fixture.py OUT [resources]` writes a network-free SEOsmith `FixtureTransport` map (57 numbered pages plus a home-page alias: 58 page entries, and up to 400 synthetic resources). Run the producer with `local-cli-fixtures,local-e2e` and `SEOSMITH_LOCAL_FIXTURES` pointing to the output.
* `seed.sh` runs `seed.sql` inside the dedicated `supabase_db_w1c8e` container and enables the wire-2 validator. Create the test owner in local Auth first and set `OWNER_ID`, `REAL_TOKEN_SHA256`, and `FIXTURE_TOKEN_SHA256`. Do not run the SQL against another database.
* `crawl.sh URL RESOURCES OUT` submits to a prestarted local SEOsmith and checks downloaded bytes, admission summary and local DB receipt. It only accepts the fixture URL or the approved site and the three candidate bounds plus 3000 for the 64-3 confirmation. `crawl.sh` expects wire-2 delivery; for the wire-1 negative confirmation, submit the same 100-page/3000-resource settings and retain the producer log and terminal failed state separately. Set `SEOSMITH_API_TOKEN`, `WEBSITE_ID`, `ADMIT`, `DB_CONTAINER=supabase_db_w1c8e`, and optionally `SEO_URL` (loopback only). Preflight inspects the listening producer and API processes, rejects their proxy environment variables, and requires their ingest and Supabase endpoints to use the dedicated loopback stack (HTP ports 3967/3969 and Supabase 56321). The database and producer must be dedicated test instances. The crawler may fetch off-host page resources; the only real-site seed is https://www.kerryhatcher.com/.
* `probe.py LOOPBACK_ENDPOINT REPORT` sends a fresh delivery for an old-receiver or disabled-validator probe. Set `HTP_INGEST_TOKEN` to the dedicated local test binding token. Verify the response and database row count separately. HTTP clients bypass ambient proxies and do not follow redirects.
* `measure.py REPORT [WORKER_SQLITE]` emits measured sizes, families, S01 counts, S05 omissions, the S14 omission table and gate results. A partial family passes only if it is truncated with `omitted_reason`, or has `coverage.unknown > 0` with `unknown_reasons` summing to that count. A section-level reason is required for unavailable sections; unavailable sections do not pass the families gate. S05 counts distinct page locators for direct graph `capture_omission` items with `collector_byte_limit`; truncated S05 items require the matching worker SQLite capture database and fail closed if it is missing or incomplete. The guidance maximum is 838,860 bytes. The result is specific to that report, not an R6 bound recommendation.
* `measure_report_capture.rs` measures per-page capture time using the HTML pages in a retained acceptance report; copy into the producer scratch checkout and build as an example with `local-e2e,local-cli-fixtures`. It permits only the approved site and waits one second between requests.
* `v1_manifest.rs` is an SEOsmith scratch example using the producer's unvalidated list-form builder to measure the v1 manifest even if it exceeds the wire-1 cap. Copy it into a detached scratch checkout's `examples` and build with `--features policy-wire-prototype`.

This is not yet a complete automated harness: stack lifecycle, fixture and live crawl orchestration, commit/finalize/capture timing, old-receiver rejection and rollback drill still require orchestration and verification. Do not treat an individual passing report as approval of an R6 bound.

The matrix runner exits nonzero for the recorded fixture-400 S01 truncation.
